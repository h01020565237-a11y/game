| 항목 | 현재 상태 |
|---|---|
| 파일 구성 | `index.html` 1개 (6,474,858 bytes, 20줄) |
| 코드(HTML+CSS+JS) | 약 56 KB (이미지 제거 시) |

| 물 지형 데이터 | base64 비트맵 1개 (11,948 bytes, 412×232 칸, 6px 격자) |

| 빌드 도구 / 테스트 | 없음 |

핵심 결론
1. 파일 크기의 **99%가 base64 이미지**입니다. 코드 자체는 작습니다. 분리만 해도 첫 로딩, 캐시, 협업(diff 충돌) 문제가 대부분 해결됩니다.
2. 확인된 **버그 8건**(아래 3장). 대부분 작은 수정으로 고칠 수 있고 게임 규칙을 바꾸지 않습니다.
3. 모바일 성능의 가장 큰 병목은 **매 프레임 2472×1392 맵 전체 그리기**, **매 프레임 DOM 갱신**, **매 프레임 배열 생성(GC)** 입니다.
4. 코드는 전역 변수 하나의 스크립트라서, ChatGPT와 동시에 수정하면 같은 줄에서 충돌이 납니다. 파일 분리 + 담당 영역 분리가 협업의 전제 조건입니다.

## 3. 버그 분석

심각도: 🔴 플레이에 영향 / 🟡 눈에 띄는 오류 / ⚪ 사소함

### 3.1 🔴 카메라가 움직이면 마우스 조준 위치가 어긋남
- 위치: `c.onmousemove` (10줄)
- 원인: 마우스의 월드 좌표를 `mousemove` 시점의 `camX/camY`로 계산해서 저장합니다. 플레이어가 움직여 카메라가 이동해도 마우스를 움직이지 않으면 좌표가 갱신되지 않습니다.
- 증상: PC에서 이동하면서 클릭 공격·소환하면 화면상의 커서와 다른 곳으로 공격이 나감.
- 수정안: 화면 좌표(`mouse.sx, mouse.sy`)를 저장하고, 공격·소환 시점에 현재 카메라로 월드 좌표를 계산.

### 3.2 🟡 대시 잔상이 다른 캐릭터 그림으로 나옴
- 위치: `draw()`의 `fx.filter(f=>f.trail)` (19줄)
- 원인: 러너·곰만 전용 이미지가 있고, 나머지 6종은 모두 `img`(소환사 1024px 시트)로 그립니다.
- 증상: 정장·쭈꾸미·줄무늬·축구·서포트가 대시하면 빨간 모자 잔상이 나타남.
- 수정안: `sheets[character]`로 잔상을 그림. 그러면 887 KB짜리 `img`가 필요 없어짐 (삭제는 승인 후).

### 3.3 🟡 봇 걷기 애니메이션이 2배속
- 위치: `move()` (11줄)와 `update()` 앞부분의 `prevX` 블록 (15줄)
- 원인: 봇이 `move()`로 움직일 때 `frame`이 한 번 증가하고, 다음 프레임 `prevX` 비교에서 한 번 더 증가합니다.
- 수정안: `prevX` 블록은 `move()`를 거치지 않은 이동(넉백 등)에만 적용.

### 3.4 🟡 이미지 로딩 전에는 캐릭터가 보이지 않음
- 위치: `renderActor()` (9줄)
- 원인: 시트가 아직 디코딩되지 않으면 `false`만 반환하고 아무것도 그리지 않습니다. 배경도 그동안 `scenery()` 대체 그림이 그려졌다가 바뀝니다.
- 수정안: 로딩 화면에서 모든 이미지 `decode()` 완료 후 게임 시작 + 로딩 실패 시 대체 도형 표시.

### 3.5 🟡 봇 정장 스킬이 벽 너머로 들어감
- 위치: `update()` 봇 스킬 (15줄, `k==='suit'`)
- 원인: 거리 230 안이면 시야(`clearLine`) 확인 없이 250 피해. 소환사 봇(180)도 같음.
- 수정안: `clearLine(a,b)` 조건 추가. (밸런스 변화가 있어 승인 필요)

### 3.6 🟡 모바일에서 안내문 숨김 CSS가 다른 요소를 가리킴 (실기기 확인 필요)
- 위치: CSS `body.mobile>div:first-of-type{display:none}` (1줄)
- 원인: `body`의 첫 번째 `div`는 조작 안내문이 아니라 `#rotateHint`입니다. 그래서 안내문이 모바일에서도 계속 보입니다.
- 영향: 캔버스 위에 예상보다 많은 요소가 있어, `calc(100dvh - 78px)` 기준으로 맞춘 캔버스와 아래쪽 재시작/무적 버튼이 `overflow:hidden` 때문에 화면 밖으로 밀릴 가능성이 높습니다. 그러면 모바일에서는 재시작할 방법이 없습니다.
- 수정안: 안내문에 id를 붙여 정확히 숨기고, 게임 종료 시 캔버스 위에 "다시 하기" 버튼 표시. (UI 배치는 ChatGPT 담당 영역이라 협의 필요)

### 3.7 ⚪ 낮은 프레임에서 게임이 느려짐
- 위치: `loop()` (19줄) `dt=Math.min(.035, …)`
- 원인: 28fps 아래로 떨어지면 게임 시간이 실제 시간보다 느리게 흐릅니다 (저사양 폰에서 슬로모션).
- 수정안: 고정 시간 간격(예: 1/60초) 업데이트 + 누적기 방식.

### 3.8 ⚪ 정리 대상 코드 (동작 영향 없음)
- `aimX/aimY`는 선언만 되고 항상 0 (소환 방향 계산에서 의미 없음)
- `rivers=[]`, `#slots` CSS 미사용
- `extraImages` 5장은 그리지 않고 분기 플래그로만 사용 (약 41 KB)
- `buildGround()`가 정글 이미지가 있어도 항상 2472×1392 캔버스를 만듦 (메모리 약 13.8 MB)
- `bearSkill()` / `#bearHeal`이라는 이름이 실제로는 모든 비소환사 캐릭터의 스킬을 담당 → 이름 정리 필요
- 몇몇 텍스트 그리기에서 `font`, `textAlign`이 이전 상태를 그대로 사용

| 매 프레임 맵 전체(2472×1392) 그리기 | `draw()`의 `g.drawImage(jungle,0,0,W,H)` | 화면은 1000×650인데 약 5.3배 넓이를 매번 확대 샘플링 | 원본 이미지에서 카메라 영역만 잘라 그리기 (9인자 `drawImage`) |
| 매 프레임 맵 전체 채우기 | `g.fillRect(0,0,W,H)` | 위와 동일한 낭비 | 정글 이미지가 있으면 생략 |
| 자기장 바깥 영역을 맵 전체 크기로 `evenodd` 채우기 | `draw()` 끝부분 | 큰 경로 채우기가 매 프레임 | 화면 영역 사각형 기준으로 그리기 |
| 번개 `shadowBlur=12` | `lightning()` | 모바일 GPU에서 매우 비쌈 | 미리 그린 글로우 스프라이트 사용, 또는 모바일에서 블러 축소 |
| 매 프레임 `createRadialGradient` | `drawPika()` | 객체 생성 | 피카츄를 오프스크린 캔버스에 8방향 미리 그리기 |
| 정글 이미지 1.48배 확대 | `jungle` 1672×941 | 흐릿함 + 매 프레임 스케일링 | 원본 해상도 이미지 요청(ChatGPT) 또는 시작 시 한 번만 확대한 캔버스 캐시 |
| 고해상도 화면 미대응 | 캔버스 1000×650 고정 | 레티나 폰에서 흐림 (대신 가벼움) | `devicePixelRatio` 반영하되 최대 1.5~2로 제한하는 옵션 |

### 4.2 DOM 갱신 (모바일에서 체감이 큼)
- `draw()`에서 매 프레임 `#hud`, `#petHUD`, `#msg`의 `textContent`를 갱신하고 `querySelector`로 다시 찾습니다.
- `touchHUD()`가 매 프레임 버튼 4개의 글자와 투명도를 바꾸고, 스와이프 중에는 `innerHTML`까지 다시 씁니다.
- 내용이 같아도 매번 쓰기 때문에 레이아웃·페인트가 계속 발생합니다.
- 개선안: 요소는 시작 시 한 번만 찾아 두고, 값이 바뀌었을 때만 쓰기. 쿨타임 숫자는 0.1초 단위로 바뀔 때만 갱신.

### 4.3 계산 / 메모리 (GC 끊김)
- `targets()`가 호출될 때마다 `[p,...bots,...boxes,...pet]` 배열을 새로 만들고 `filter`합니다. 봇 7명 × 매 프레임 + **투사체 1개 × 이동 단계마다** 호출 → 초당 수천 개의 임시 배열.
- `visible()` → `inBush()`가 덤불 22개를 매번 검사. 액터의 덤불 여부는 프레임당 한 번만 계산하면 됩니다.
- `sort((a,b)=>dist(..)-dist(..))`처럼 비교 함수 안에서 `Math.hypot`을 반복 호출 → 최솟값 찾기(선형 탐색)로 충분.
- 봇마다 매 프레임 `loot.filter`, `pickup()`의 `filter + sort`.
- `fx`, `shots`를 매 프레임 `filter`로 새 배열 생성.
- `move()` 한 번에 `boxes.some` 2번 + `blocked` 2번 + `terrain`(물 비트맵 5점) 2번.
- 개선안: 프레임 단위 캐시(살아 있는 액터 목록, 덤불 여부), 제곱 거리 비교, 배열 재사용(swap-remove), 맵 충돌을 격자(그리드)로 미리 굽기.

> 지금 규모(액터 8~9명)에서는 계산 자체보다 **GC로 인한 순간 끊김**이 문제입니다. 저사양 안드로이드에서 특히 드러납니다.

### 4.4 AI 품질과 성능
- 경로 탐색이 없어서 벽·물 뒤의 대상을 향해 계속 밀다가 좌우 회피 1회만 시도합니다. 자기장 밖에서는 중앙으로 직선 이동하다 물·벽에 걸려 죽기도 합니다.
- 펫은 회피 로직도 없어 벽에 끼입니다.
- 개선안: 물 비트맵과 벽으로 만든 격자(예: 24px)에서 A* 경로를 0.3~0.5초마다 갱신 + 직선 시야가 열리면 바로 직진. 봇 1명당 계산을 프레임마다 나눠서(시간 분할) 처리하면 모바일에서도 부담이 적습니다.
- 이것은 AI 동작이 바뀌는 작업이므로 승인 후 진행합니다.

### 4.5 로딩
- 6.47 MB HTML을 다 받아서 파싱해야 화면이 뜹니다. base64는 원본보다 약 33% 큽니다.
- 이미지가 HTML 안에 있으니 브라우저 캐시를 따로 쓸 수 없습니다. 코드를 한 글자만 바꿔도 6.5 MB를 다시 받아야 합니다.
- 실제로 쓰지 않는 데이터: `img` 887 KB (3.2 수정 시), `extraImages` 41 KB.

### 5.2 단계별 진행 (각 단계마다 동작이 완전히 같아야 함)

| 단계 | 작업 | 위험도 | 확인 방법 |
|---|---|---|---|
| 1 | base64 이미지 17개 + 물 비트맵을 **바이트 그대로** `assets/`로 추출, 코드의 `src`만 경로로 교체 | 낮음 | 추출 파일 해시 = 원본 base64 디코딩 해시 |
| 2 | CSS를 `css/`로 이동 (선택자·값 그대로) | 낮음 | 화면 캡처 비교 (PC/모바일) |
| 3 | JS를 **일반 `<script>` 여러 개**로 순서대로 분할 (전역 변수 그대로 유지) | 낮음 | 같은 시드로 플레이 로그 비교 |
| 4 | 하드코딩 데이터(무기·장비·포켓몬·벽·덤불·상자·스폰)를 `js/data/`로 이동 | 중간 | 값 비교 스크립트 |
| 5 | ES 모듈로 전환, 전역 변수를 `state` 객체로 정리 | 중간 | 3단계와 동일 |
| 6 | 단일 파일 빌드 스크립트 (`dist/index.html`) | 낮음 | 빌드 결과와 분리 버전 동작 비교 |

- 3단계에서 비교 테스트를 하려면 `Math.random()`을 시드가 있는 난수 함수로 바꾸는 작업이 필요합니다 (게임 규칙은 그대로, 난수 공급원만 교체).
- 이미지 형식 변경(PNG→WebP)이나 해상도 변경은 그림이 바뀌므로 이 단계에 넣지 않고, ChatGPT와 협의 후 별도로 진행합니다.

### 5.3 주의할 점: 파일을 더블클릭해서 여는 방식
- 분리된 구조, 특히 ES 모듈은 `file://`로 직접 열면 브라우저 보안 정책 때문에 동작하지 않습니다.
- 해결책 두 가지를 같이 씁니다.
  1. **GitHub Pages**로 배포 (`main` 브랜치 또는 `gh-pages`) → 폰에서 링크로 바로 플레이
  2. `tools/build-single.py`로 지금처럼 **하나로 합친 `index.html`**도 계속 만들어 둠 → 파일로 공유·오프라인 실행 가능

### 5.4 협업 규칙 제안 (ChatGPT와 충돌 방지)
- 브랜치: `main`(승인된 버전만), `claude-dev`(엔진·전투·AI·성능), `chatgpt-dev`(기획·캐릭터·그래픽·맵·UI)
- 파일 담당: `js/engine`, `js/game`, `js/render`는 Claude / `assets`, `css`, 그리고 기획 문서는 ChatGPT / `js/data`는 공동 (수치 변경은 PR 설명에 이유 기재)

## 6. 모바일 게임 최적화 방안

### 6.1 우선순위 (효과 대비 작업량 순)

| 순위 | 항목 | 기대 효과 |
|---|---|---|
| 1 | 맵 배경을 카메라 영역만 그리기, 전체 `fillRect` 제거, 자기장 오버레이를 화면 기준으로 그리기 | GPU 채우기 부담 약 5배 감소 |
| 2 | HUD DOM은 값이 바뀔 때만 갱신, 요소 캐시 | 레이아웃 재계산 제거, 프레임 안정 |
| 3 | 에셋 분리 + 로딩 화면 + `img.decode()` 후 시작 | 첫 화면 속도, 재방문 시 캐시, 3.4 버그 해결 |
| 4 | 임시 배열 생성 제거 (`targets`, `sort`, `filter`) | GC 끊김 감소 |
| 5 | 고정 시간 간격 루프 | 저사양 폰에서 슬로모션 제거 (3.7) |
| 6 | `shadowBlur`·그라디언트를 미리 그린 스프라이트로 대체 | 번개 기술 사용 시 프레임 드랍 제거 |
| 7 | 충돌 격자 미리 계산 (벽 + 물 + 맵 경계) | `move()` 비용 감소, AI 경로 탐색 기반 |
| 8 | 백그라운드 전환 시 자동 일시정지 (`visibilitychange`) | 배터리, 복귀 시 사망 방지 |

### 6.2 모바일 화면 / 조작
- **안전 영역(노치)**: `viewport-fit=cover`는 있지만 `env(safe-area-inset-*)` 여백이 없어 아이폰 가로 화면에서 버튼이 노치·홈 바에 가릴 수 있습니다.
- **버튼 반응 속도**: 대시·획득·스킬2 버튼이 `onclick`이라 손을 뗄 때 발동합니다. 공격·조이스틱처럼 `pointerdown`으로 바꾸면 반응이 빨라집니다.
- **캔버스 터치**: 터치 모드에서도 캔버스를 탭하면 호환 마우스 이벤트로 탭한 위치에 공격이 나갈 수 있습니다. 터치 모드에서는 캔버스 마우스 입력을 무시하는 것이 안전합니다.
- **재시작/일시정지**: 캔버스 위 오버레이 버튼 필요 (3.6). 배치·디자인은 ChatGPT 담당.
- **전체 화면 / 화면 꺼짐 방지**: 시작 버튼에서 `requestFullscreen()`(안드로이드)과 Wake Lock API 적용 검토. iOS Safari는 전체 화면이 제한적이므로 "홈 화면에 추가"(PWA) 안내가 현실적입니다.
- **해상도 옵션**: 고화질(devicePixelRatio 최대 2) / 절전(현재 1000×650, 30fps 제한) 선택.

### 6.3 에셋 용량
- 현재 이미지 총 약 4.8 MB. 그림을 바꾸지 않고 줄일 수 있는 것:
  - 대시 잔상 수정 후 `img`(887 KB) 제거 → 승인 필요
  - `sheets.stripe` PNG → WebP 무손실/고품질 변환 → ChatGPT 확인 필요
- 그림이 바뀌므로 ChatGPT와 협의할 것:
  - 정글 배경을 실제 맵 크기(2472×1392)로 다시 받기 (지금은 확대되어 흐림)
  - 캐릭터 시트는 96px 칸을 68px로 줄여서 그리므로, 모바일용 72px 시트를 따로 두면 용량·메모리 절반 가까이 감소
- 오프라인/재방문: Service Worker로 에셋 캐시 (PWA). GitHub Pages에서 동작.

### 6.4 측정 계획
- 개발용 FPS·프레임 시간 표시(디버그 버튼과 같이), 프레임 시간 95퍼센타일 기록
- 테스트 기기 기준: 저사양 안드로이드 1대 + 아이폰 1대, 봇 7명 + 번개 기술 + 자기장 최소 상태에서 측정
- 최적화 전후 수치를 이 문서에 추가

### 10.1 공격 모션 (ATTACK_ANIMATION.md)
- 무기별 준비/공격/복귀 시간(ms)을 그대로 데이터화 (`WEAPON_FEEL.phases`): 맨손 40/70/90, 검 60/90/120, 망치 90/100/160, 권총 30/50/100, 산탄총 40/70/150, 저격총 50/60/180, 수류탄 80/80/120
- 맨손: 당겼다 지르기 / 검: 손 기준 회전 + 베기 궤적 / 망치: 들어올림 → 내려찍기 → 충격파 / 권총·산탄총·저격총: 공격 단계에만 총구 섬광(짧은·넓은·긴), 반동 / 수류탄: 팔 투척, 손을 떠난 뒤 기존 0.8초 폭발
- 8방향 손 앵커 + 방향별 앞뒤 그리기 순서 (`HAND_ANCHORS`), 캐릭터별 보정 (`HAND_OFFSET`)
- 작은 몸 반동 (근접은 앞으로, 총은 뒤로), 이동 그림은 왜곡하지 않음
- 공격 실패(탄창·수류탄 부족) 시 모션·소리 없음, 판정·충전·쿨타임은 그대로
- 사망: 0.6초 바래며 가라앉는 임시 효과 / 총알은 판정 좌표 그대로, 그림만 총구 높이로
- 효과음: 첨부 SFX 19종은 이미 적용된 파일과 바이트 단위로 같음. 파일이 없는 소리(스킬·소환·배경음악)는 사양대로 무음 (`AUDIO_SYNTH_FALLBACK = false`)
- 검수 도구: `tools/motion_strip.py` (무기별 프레임 띠 이미지)

미통과·확인 필요:
- **곰 질주 4족 애니메이션 (QA_PLAN P0)**: ART_DIRECTION 의 "8명 얼굴·외형 유지"와 충돌 (후보 시트는 다른 얼굴). 최신 지시(기존 외형 유지)에 따라 꺼 둠 → 결정 필요
- **캐릭터 시트 검수 (ART_DIRECTION)**: 경수만 발 위치가 고정. 현곤·기섭·상훈·재한·은숙은 같은 방향 안에서 발 높이가 4~11px 흔들려 달릴 때 위아래로 튐. 곰은 방향당 1프레임(달리기 없음) + 2칸 잘림 → 그래픽 보정 요청
- **배경과 충돌 비교**: 위 벽 4개 수정. 그 밖에 그림에는 덤불인데 충돌 목록에 없는 작은 풀숲이 여러 곳 있음(장식인지 기획 확인 필요)
- **밸런스 관찰**: 상자 24개가 모두 열리고 AI 가 수류탄을 쓰면서 시뮬레이션(무작위 입력)에서 플레이어가 8캐릭터 모두 패배. 실제 플레이 확인 후 AI 반응·드롭 확률 조정 제안

### 같이 반영한 조작 개선
- 무기 쥐는 위치: 8방향 손 위치를 턱 → 배 높이로 내리고, 방향별로 무기가 몸 뒤/앞에 그려지게 조정. 무기 크기 축소, 대기 자세 각도 추가.
- 현곤 소환 메뉴: 3마리를 왼쪽·왼쪽 위·위 부채꼴로 배치(아이콘 크기 기준 간격 계산) → 화면 오른쪽 끝에서 겹치지 않음.
- 소환 위치 지정: 포켓몬을 고르면 조준 모드(사거리 220 원 + 조준점). 맵을 탭/드래그해서 위치를 정하고 떼면 투척, 소환 버튼 탭은 현재 조준점으로 투척, 버튼에서 끌어 방향·거리 조준, 가운데로 되돌리면 취소, 5초 무입력 시 자동 취소. 벽·지형·상자 위는 빨간색으로 표시되고 던지지 않음. PC는 기존처럼 Q 로 마우스 위치(220 이내)에 투척.

## 캐릭터 선택창 Portraits V2 적용
- 얼굴 아이콘 8종을 `assets/portraits/<id>.png`(PNG)로 교체. 원본이 시안에서 잘라낸 것이라 위아래 바깥 액자 띠와 이웃 칸 선택선(현곤 모서리 노란 선)이 붙어 있어 `tools/clean_portraits.py`로 카드 영역(y 15~240)만 남기고 모서리를 둥글게 처리. 그림 자체는 수정하지 않음.
- 타일 구조: `[얼굴 칸(.char-face, 여백 6%, object-fit: contain)]` + `[이름 칸(.char-name)]` 분리. 선택 테두리는 타일 바깥. 배경 그라디언트·4×2 배열 유지.
- 배치 순서 고정 `LOBBY_ORDER`: 동기·현곤·은숙·기섭 / 상훈·경수·재한·정용 (`CHARACTER_ORDER`는 기존 로직용으로 그대로 둠).
- 영입 상태 `ROSTER`: 처음엔 동기만 영입, 재한·정용은 "출시 예정". 미영입은 어둡게 + 자물쇠. `ROSTER.testMode = true`면 미영입도 선택·플레이 가능(현재 테스트용), `false`면 선택 버튼 비활성.
- 정용은 빨간 목도리 신규 외형 유지(롤백 안 함). 전투 스프라이트는 기존 유지.

## 싱글 웨이브 생존전 프로토타입 (현곤 영입 미션, docs/SINGLE_WAVE_PROTOTYPE.md)
- 로비 "싱글 미션" → 미션 목록(현곤만 구현, 나머지는 선행 조건·준비 중 표시) + 스토리 극장.
- 동기로 기존 정글 맵에서 3웨이브. 1: 근접 8 / 2: 근접 10 + 원거리 4 / 3: 일반 12(근접 8 + 원거리 4) + 보스. 순차 등장, 전원 처치 시 다음 웨이브. 자기장 끔.
- 1·2웨이브 후 전투 정지, 6종 중 중복 없이 3장 → 1장 선택. 효과는 이번 판의 p 에만 붙음 (p 는 판마다 새로 만들어짐) → 배틀로얄과 분리.

## 주엽공고 타이틀 화면
- 처음 열면 타이틀 → "시작하기"(또는 Enter/Space) → 기존 메인 로비. 로비·전투 코드는 그대로.
- 레이어: 학교 배경(화면 전체 cover) → 16:9 무대(로고 / 캐릭터 / UI 버튼). 16:9 보다 넓거나 좁은 화면은 무대를 16:9 로 유지하고 배경이 나머지를 채움. 폰 세로 회전 모드도 동일.
- 원본 PNG(assets/title_screen/*.png, 4MB)는 보관하고 게임에서는 WebP(배경 391KB, 로고 234KB, 로고는 투명 여백만 잘라냄) 사용.
- 캐릭터: 확정된 전신 이미지(LOBBY_ART.full)를 별도 레이어로 배치. `js/data/title.js`의 `TITLE_CHARACTERS` 목록만 바꾸면 인원 수에 맞춰 자동 배치(가운데 시작 버튼 자리 비움, 앞줄/뒷줄 번갈아). 개별 x·y·키·좌우 반전 지정 가능.
- 시작·설정·버전은 HTML UI. 설정 = 배경음·효과음·음소거(기존 사운드 설정 공유).

## 스킬·포켓몬 버튼 길게 누르기 설명창
- 0.45초 이상 누르면 버튼 위에 설명창(이름·효과·쿨타임/능력치). 설명을 본 뒤 떼면 사용하지 않음. 짧게 탭하면 사용.
- 스킬 버튼(Q·E)은 길게 누르기와 구분하려고 누르는 순간 → 손을 뗄 때 발동으로 변경.
- 포켓몬 버튼: 설명을 보다가 끌기 시작하면 설명 닫고 조준으로 전환.
- 데이터: 캐릭터 스킬은 CHARACTER_INFO.skills, 포켓몬은 새 PET_INFO (js/data/pets.js, command() 수치와 동일하게 유지).
- 미영입 캐릭터 선택 가능은 ROSTER.testMode = true (임시). 정식 영입 시스템 오픈 시 false.

- 캐릭터 선택창 현곤 포켓몬 칸에도 같은 공통 설명창 연결 (길게 누르기 / PC 마우스 올리기). 설명만 본 경우 선택이 바뀌지 않음. 스크롤 영역 안 버튼도 위치가 맞도록 설명창 위치 계산에 스크롤 반영.
